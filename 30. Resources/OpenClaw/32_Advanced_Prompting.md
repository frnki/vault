# 32. 에이전틱 리터러시: LLM 성능 한계 돌파 전략 (Advanced Prompting)

프랭크, 에이전트의 지능은 모델의 파라미터 수보다 **'우리가 문제를 정의하는 방식'**에 더 크게 좌우됩니다. 오늘은 단순히 명령을 내리는 수준을 넘어, 에이전트가 스스로 추론하고 검증하게 만드는 **고급 프롬프팅(Advanced Prompting)** 전략을 다룹니다.

---

### 1. 왜 이 기능이 중요한가 (dgng 운영 맥락)
dgng(디지털 노마드 가이드) 운영 시, 에이전트가 생성하는 콘텐츠나 코드의 '환각(Hallucination)'은 치명적입니다. 
- **복합 의사결정:** "이 플러그인을 설치할까?"라는 질문에 단순히 YES/NO가 아닌, 충돌 가능성과 보안 리스크를 스스로 검토해야 합니다.
- **품질의 균일화:** 프랭크가 직접 검수하지 않아도, 에이전트가 스스로 '자기 비판(Self-Criticism)' 과정을 거쳐 최상급 결과물만 내놓게 만듭니다.

### 2. 핵심 개념 설명
- **Chain-of-Thought (CoT):** "생각의 사슬". 에이전트에게 "단계별로 생각하라"고 명시하여 추론 과정을 노출시킵니다.
- **Self-Refinement:** 에이전트가 첫 번째 초안을 작성한 후, 스스로 취약점을 찾아 수정하게 하는 반복 루프입니다.
- **Role-Playing Contextualization:** 단순한 '비서'가 아니라, '10년 차 시스템 아키텍트'와 같이 극도로 구체적인 페르소나를 부여해 지식의 인출 범위를 좁힙니다.

### 3. 실전 예시

#### 예시 1: CoT를 활용한 코드 리뷰
```markdown
"dgng 웹사이트의 다음 JS 코드를 리뷰해줘. 
먼저 (1) 코드의 의도를 파악하고, (2) 잠재적인 메모리 누수 지점을 찾고, (3) 최적화된 대안을 제시해. 
각 단계별로 생각 과정을 먼저 적고 최종 코드를 보여줘."
```

#### 예시 2: Self-Refinement 시스템 프롬프트
```markdown
"너는 dgng의 콘텐츠 에디터야. 
1. 요청받은 주제로 블로그 포스트를 작성해.
2. 작성 후, 스스로 '가독성', 'SEO 최적화', '팩트 체크' 관점에서 0-10점 사이로 점수를 매겨.
3. 9점 미만인 항목이 있다면, 그 이유를 분석하고 직접 수정해서 최종본을 제출해."
```

#### 예시 3: Few-Shot을 통한 톤앤매너 고정
```markdown
"프랭크의 말투는 냉철하지만 따뜻해.
Input: '날씨가 좋네요.' -> Output: '생산성을 높이기 최적의 기온입니다. 집중하기 좋은 환경이군요.'
Input: '서버가 다운됐어.' -> Output: '상황 인지했습니다. 즉시 로그 분석 후 복구 플랜 보고하겠습니다.'
Input: [현재 상황] -> Output: "
```

### 4. dgng 즉시 적용 가능한 템플릿
에이전트에게 난해한 작업을 맡길 때 이 구조를 복사해서 사용하세요.

```markdown
# MISSION: [작업명]
# ROLE: 너는 [구체적인 전문가]로서 행동한다.
# CONTEXT: 현재 dgng의 상황은 [상세 설명]이다.
# THINKING PROCESS: 
1. 문제를 최소 단위로 분해한다.
2. 각 단위별 해결책을 도출한다.
3. 해결책 간의 충돌 가능성을 검토한다.
# CONSTRAINTS:
- 답변은 반드시 한국어로 작성한다.
- 불확실한 정보는 '추측됨'이라고 명시한다.
# OUTPUT: [최종 결과물 형식]
```

### 5. 함정 및 주의사항
- **프롬프트 비대화:** 프롬프트가 너무 길어지면 오히려 핵심 지시사항을 놓치는 'Lost in the Middle' 현상이 발생합니다. 중요한 지시는 **맨 앞**이나 **맨 뒤**에 배치하세요.
- **무조건적인 CoT:** 단순한 작업에 CoT를 강제하면 토큰 비용만 늘어납니다. 직관적인 작업은 바로 실행하게 하세요.

### 👨‍🏫 선생님의 통찰
프랭크, "에이전트가 똑똑하지 않다"고 느껴질 때는 대부분 **"내가 질문을 너무 모호하게 던지지는 않았나?"**를 먼저 돌아봐야 합니다. 에이전트에게 '생각할 시간(Thinking Time/Tokens)'을 충분히 주는 것이 인공지능 리터러시의 핵심입니다. 도구는 준비되었습니다. 이제 프랭크의 정교한 설계가 필요할 때입니다.
