# 38. 노드(nodes) 원격 실행/알림: 현장 디바이스를 운영에 붙이기

## 1) 왜 이 기능이 중요한가 (dgng 운영 맥락)
현장(매장/창고/사무실)의 ‘상태’는 보통 사람의 눈·손에 묶여 있습니다. dgng 운영에서 장애/이상(온도, 출입, 재고, 장비 다운)을 **알림→증거수집→조치**로 묶지 못하면, 대응이 늦고 원인도 남지 않습니다. `nodes`는 OpenClaw를 **현장 디바이스(폰/라즈베리파이/노트북)**와 연결해 “원격 눈(카메라/스크린)”과 “원격 손(명령 실행/앱 열기/알림)”을 제공합니다. 즉, 운영을 ‘사람 호출’에서 ‘자동 절차’로 바꾸는 레버입니다.

## 2) 핵심 개념 설명 (간결)
- **Node**: Gateway에 페어링된 원격 디바이스. 각 노드는 실행/카메라/스크린/알림 기능을 노출.
- **run**: 노드 OS에서 커맨드 실행(로그 수집, 서비스 재시작 등).
- **notify**: 현장 담당자 디바이스에 푸시(overlay 포함)로 즉시 확인 유도.
- **camera_snap / screen_record**: “현재 증거”를 남기는 관측 도구.

## 3) 실전 예시 (3–5개)
### 예시 A. 노드 목록/상태 확인
```bash
openclaw nodes status
openclaw nodes describe --node <node-id>
```
(에이전트 도구로는 `nodes(action:"status")`, `nodes(action:"describe", node:"...")`)

### 예시 B. 현장 담당자에게 즉시 확인 알림
```json
nodes({
  "action":"notify",
  "node":"store-ipad",
  "title":"[dgng] POS 상태 확인",
  "body":"POS 앱 멈춤 의심. 1) 재실행 2) 1분 후 다시 보고",
  "priority":"timeSensitive",
  "delivery":"overlay"
})
```

### 예시 C. 라즈베리파이에서 로그 수집 + 서비스 재시작
```json
nodes({
  "action":"run",
  "node":"dgng-pi",
  "command":["bash","-lc","sudo systemctl status mysvc --no-pager; sudo systemctl restart mysvc; tail -n 50 /var/log/mysvc.log"],
  "commandTimeoutMs":60000
})
```

### 예시 D. 출입문 쪽 카메라 스냅샷으로 상황 확인
```json
nodes({
  "action":"camera_snap",
  "node":"front-iphone",
  "facing":"back",
  "maxWidth":1280,
  "quality":80,
  "delayMs":1200
})
```

### 예시 E. 화면 녹화로 “재현 불가” 이슈를 증거화
```json
nodes({
  "action":"screen_record",
  "node":"kiosk-android",
  "duration":"20s",
  "includeAudio":false,
  "fps":24,
  "needsScreenRecording":true
})
```

## 4) dgng 즉시 적용 템플릿 (운영 플로우)
**트리거(사람/크론/모니터링) → 알림 → 증거수집 → 조치 → 보고**
```text
1) nodes.notify: “이상 감지, 2분 내 확인” (overlay, timeSensitive)
2) nodes.camera_snap or nodes.screen_record: 현장 증거 확보
3) nodes.run: 로그/상태 덤프 + 1차 복구(재시작)
4) 결과를 한 줄 요약(원인/조치/다음 액션)로 운영 노트에 남김
```

## 5) 함정 및 주의사항
- **권한**: `sudo`, 화면 녹화 권한, 카메라 권한이 없으면 실패. 사전에 노드별 퍼미션 체크.
- **타임아웃/블로킹**: `run`은 장시간 커맨드(대용량 압축/업데이트)로 막히기 쉬움 → `commandTimeoutMs`와 분할 실행.
- **프라이버시/규정**: 카메라/녹화는 촬영 범위·보관 정책을 명확히(특히 매장/직원).
- **노드 식별**: 노드 이름을 운영 친화적으로(예: `store-frontdoor-cam`, `dgng-pi-1`).

## 6) 👨‍🏫 선생님의 통찰
노드 운영의 핵심은 “원격으로 뭔가 한다”가 아니라, **재현 가능한 절차를 만든다**는 데 있습니다. 알림만 보내면 사람의 기억에 의존하지만, 알림+스냅샷+로그를 같이 남기면 다음번엔 ‘추측’이 아니라 ‘증거’로 대응합니다. dgng에선 작은 이상이 반복될 때 비용이 커지니, 노드를 **증거 자동 수집 장치**로 먼저 쓰고, 그 다음에 복구 자동화(run)를 붙이세요.
