# 40. 세션 오케스트레이션: `sessions_spawn`로 백그라운드 작업 돌리기

## 1) 왜 이 기능이 중요한가 (dgng 운영 맥락)
운영 중엔 “지금 당장 답변”과 “시간이 걸리는 조사/분석/코드 수정”이 동시에 터집니다. 메인 대화(텔레그램)는 끊기면 안 되는데, 한 건이 길어지면 전체 대응이 느려져요. `sessions_spawn`는 **작업을 분리(격리 세션)**해서 돌리고, 끝나면 **요약을 메인으로 자동 리턴**하게 만들어 **운영 속도와 안정성**을 같이 올립니다. dgng에서 특히 유용한 지점은: (1) 장애 원인 탐색, (2) 로그/대시보드 수집, (3) 문서/런북 생성, (4) 코드/설정 변경안 초안 작성 같은 “30~90초 이상” 작업입니다.

## 2) 핵심 개념 (간결)
- **메인 세션**: 지금 대화가 흐르는 곳(즉시 응답용)
- **격리(isolated) 세션**: 스폰된 서브 에이전트가 혼자 일하는 공간(장기/복잡 작업용)
- `sessions_spawn`: 서브 에이전트를 **비동기로 실행**하고, 완료 요약을 메인으로 **announce**
- `sessions_list/history/send`: 스폰된 세션을 **추적/추가 지시/회수**하는 관리 도구

## 3) 실전 예시 (3~5개)
### 예시 1) “원인 조사”를 백그라운드로
```json
{ "tool": "sessions_spawn", "task": "dgng 에러 로그 패턴 3가지 가설과 확인 절차 제시", "label": "dgng-incident-hypotheses", "runTimeoutSeconds": 600 }
```

### 예시 2) 특정 세션 상태 확인
```json
{ "tool": "sessions_list", "kinds": ["isolated"], "limit": 10, "messageLimit": 1 }
```

### 예시 3) 스폰 세션에 추가 요구사항 투입(중간 수정)
```json
{ "tool": "sessions_send", "sessionKey": "<spawned_session_key>", "message": "가설마다 재현 절차 + 롤백 플랜도 포함해줘" }
```

### 예시 4) 결과가 부족하면 히스토리로 맥락 회수
```json
{ "tool": "sessions_history", "sessionKey": "<spawned_session_key>", "limit": 20 }
```

### 예시 5) 코드 변경/문서 작성도 분리
```json
{ "tool": "sessions_spawn", "task": "dgng 운영 런북: 장애 감지→증거 수집→조치 체크리스트를 1페이지로", "label": "dgng-runbook", "runTimeoutSeconds": 900, "cleanup": "keep" }
```

## 4) dgng 즉시 적용 템플릿
아래 템플릿을 그대로 복사해서 ‘스폰’ 지시로 쓰세요.

**템플릿(조사/개선 과제용)**
- 목표: (무엇을 결정/산출할지)
- 입력: (로그/지표/제약)
- 출력 형식: ① 결론 ② 근거 ③ 실행 체크리스트 ④ 롤백/리스크
- 타임박스: 10분

```text
sessions_spawn 작업:
[목표] dgng에서 <문제/기회>에 대한 최선의 실행안 도출
[제약] 운영 중단 최소화, 변경은 단계적
[출력] 결론/근거/실행순서/검증/롤백
[타임박스] 10분
```

## 5) 함정 및 주의사항
- **스폰 남발**: 동시에 너무 많이 돌리면 관리가 어려워집니다. “1건=1산출물”로 라벨을 꼭 붙이세요.
- **컨텍스트 누락**: 서브 세션은 메인 맥락을 자동으로 다 알지 못합니다. 필요한 로그/조건을 task에 명시하세요.
- **타임아웃 관리**: `runTimeoutSeconds`를 짧게 잡고, 부족하면 2차 스폰으로 쪼개는 게 안전합니다.
- **cleanup 전략**: 반복 운영 템플릿은 `keep`, 단발 조사/테스트는 `delete`가 비용/정리 측면에서 유리합니다.

## 6) 👨‍🏫 선생님의 통찰
운영은 “생각하는 시간”과 “응답하는 시간”이 섞이면 반드시 느려집니다. `sessions_spawn`는 팀에서 **담당자 분리**를 자동으로 해주는 도구예요. 프랭크의 dgng 운영 루프를 이렇게 바꾸면 좋습니다:
- 메인: 상황 정리/의사결정/커뮤니케이션
- 서브: 조사/대안 생성/런북 작성/자동화 초안
이 구조가 잡히면, 같은 시간에 더 많은 이슈를 ‘끝까지’ 처리하게 됩니다.
