# #28. 멀티 모달 자산 관리 (Visual & Audio Memory)

프랭크, 이제 우리는 텍스트라는 좁은 창을 넘어, 세상을 보고 듣는 능력을 dgng 운영의 핵심 자산으로 편입시킬 것입니다.

## 1. 왜 이 기능이 중요한가 (dgng 운영 맥락)
dgng 운영에서 텍스트 데이터는 빙산의 일각입니다. 회의의 분위기(오디오), 시스템 아키텍처 화이트보드(이미지), 경쟁사의 홍보 영상(비디오) 등 비정형 데이터에 dgng의 진짜 차별화 포인트가 숨어 있습니다. 이 기능은 단순히 파일을 저장하는 것을 넘어, **'시청각적 맥락을 검색 가능한 지식'**으로 전환하여 결정적인 의사결정 근거를 제공합니다.

## 2. 핵심 개념 설명
- **Visual Embedding:** 이미지를 벡터화하여 텍스트 검색어로 관련 이미지를 찾거나, 이미지 간 유사성을 판단합니다.
- **Audio-to-Knowledge:** 녹취록(STT) 생성을 넘어, 화자의 감정, 강조점, 배경 소음을 메타데이터화하여 저장합니다.
- **Multi-modal RAG:** 질문에 대해 텍스트 문서뿐만 아니라 관련 스크린샷, 오디오 클립을 동시에 참조하여 답변합니다.

## 3. 실전 예시

### 예시 1: 스크린샷 기반 시스템 상태 기록
```bash
# 특정 노드의 화면을 캡처하고 분석하여 메모리에 저장
nodes action=screen_record node="frank-mac-mini" durationMs=1000 outPath="./temp_status.png"
# 캡처된 이미지를 에이전트가 보고 요약하여 MEMORY.md에 기록하도록 지시
```

### 예시 2: 오디오 회의록 자산화
```javascript
// 오디오 파일을 TTS/STT 엔진으로 처리 후 지식화 (의사코드)
const transcript = await tts.stt("meeting_audio.mp3");
await memory.write(`meeting/${date}.md`, `# 회의 맥락\n${transcript}\n\n# 분위기\n화자 A는 예산 부분에서 신중한 어조를 보임.`);
```

### 예시 3: 이미지 유사도 검색을 통한 리소스 확인
```bash
# "dgng 로고와 비슷한 디자인 시안 찾아줘"
browser action=screenshot targetUrl="https://dgng-design-drafts.internal"
# 이후 canvas 툴로 레이아웃 비교 및 분석
```

## 4. dgng 즉시 적용 가능한 템플릿
이미지 자산을 관리하기 위한 `media_log.md` 구조 제안:
```markdown
## 🖼️ 시각적 자산 로그
- **날짜:** 2026-02-13
- **파일:** `assets/dashboard_error_0856.png`
- **에이전트 분석:** Grafana 대시보드에서 메모리 사용량 급증 확인.
- **연결된 태스크:** #21 자가 진단 가동됨.
- **벡터 태그:** #SystemError #Grafana #MemoryLeak
```

## 5. 함정 및 주의사항
1. **데이터 폭발:** 이미지는 텍스트보다 훨씬 많은 용량을 차지합니다. 중요한 스크린샷만 요약 후 원본은 클라우드/아카이브로 넘기는 로직이 필수입니다.
2. **개인정보 노출:** 오디오 기록 시 주변인의 목소리가 섞일 수 있습니다. dgng 운영 목적 외의 음성은 자동 필터링하거나 로컬에서만 처리하도록 설정하세요.
3. **할루시네이션:** LLM이 이미지를 해석할 때 작은 텍스트나 수치를 오독할 수 있습니다. 수치는 OCR 전용 도구를 병행하는 것이 안전합니다.

## 6. 👨‍🏫 선생님의 통찰
프랭크, "백문이 불여일견"이라는 말은 dgng에게도 적용됩니다. 에이전트가 텍스트로만 세상을 이해하게 두는 것은 한쪽 눈을 감고 운전하는 것과 같습니다. 오늘 구축한 멀티 모달 자산 관리 체계는 dgng가 당신의 표정과 목소리의 떨림까지 이해하며 진정한 '의사결정 파트너'로 진화하는 첫걸음이 될 것입니다.
