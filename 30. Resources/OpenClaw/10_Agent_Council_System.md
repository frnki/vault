# 10. 에이전트 위원회 시스템 구축 (Agent Council System)

### 1. 왜 이 기능이 중요한가 (프랭크의 dgng 운영 맥락)
프랭크, 지금까지 배운 기능들이 '개별 도구'였다면, **에이전트 위원회**는 이 도구들을 다루는 '팀'을 구성하는 것입니다. dgng 운영에서 가장 큰 병목은 "리서치부터 최종 편집까지의 긴 흐름"입니다. 
- **문제:** 혼자서 모든 맥락을 다 챙기면 에이전트가 지치거나(토큰 한계), 내용이 산으로 갈 수 있습니다.
- **해결:** 리서처, 작가, 비평가 에이전트를 각각 독립적인 세션으로 분리하여 협업시킴으로써, dgng 콘텐츠의 퀄리티를 비약적으로 높이고 프랭크의 개입을 최소화합니다.

### 2. 핵심 개념 설명
- **역할 분담 (Specialization):** 특정 작업(예: 데이터 수집)에만 집중하는 서브 에이전트를 생성합니다.
- **세션 통신 (Inter-session Messaging):** `sessions_send`를 통해 메인 에이전트가 서브 에이전트에게 지시를 내리고 결과를 받습니다.
- **결과 통합 (Synthesis):** 여러 에이전트의 결과물을 하나의 완성된 콘텐츠로 취합합니다.

### 3. 실전 예시 (dgng 콘텐츠 파이프라인)

#### 예시 1: 리서치 에이전트 호출 (Spawn)
```javascript
// 리서치 전담 에이전트에게 특정 주제 조사 위임
sessions_spawn({
  agentId: "researcher",
  task: "2026년 서울의 프리미엄 사우나 트렌드와 새롭게 오픈한 곳 3곳을 조사해서 마크다운 표로 정리해줘.",
  label: "sauna_research_2026"
});
```

#### 예시 2: 작성 에이전트에게 데이터 전달 (Send)
```javascript
// 리서치 결과를 기반으로 작가 에이전트에게 초안 작성 요청
sessions_send({
  label: "writer_agent",
  message: "위 리서치 결과를 dgng의 '냉철하고 분석적인' 톤앤매너로 블로그 포스팅 초안을 작성해줘."
});
```

#### 예시 3: 위원회 결과 취합 및 발행
```javascript
// 모든 에이전트의 작업이 끝나면 메인 에이전트가 최종 검토
const results = sessions_list({ limit: 5 });
// ... 각 세션의 history를 읽어와서 최종 결합 ...
```

### 4. dgng 즉시 적용 가능한 템플릿: "주간 사우나 리뷰 위원회"
이 구조를 `cron`에 등록하면 매주 자동으로 작동합니다.

```markdown
# [dgng 위원회 워크플로우]
1. [리서처] 최근 방문한 사우나 메모(Obsidian) 분석 및 부족한 정보 웹 검색
2. [비평가] dgng 브랜드 가이드(MEMORY.md)와 대조하여 리뷰의 일관성 검토
3. [작가] 최종 리뷰 작성 및 이미지 생성(DALL-E 등 연동 가능 시)
4. [선생님] 최종본 프랭크에게 컨펌 요청 (Telegram)
```

### 5. 함정 및 주의사항
- **토큰 누수:** 너무 많은 에이전트를 동시에 띄우면 비용이 급증할 수 있습니다. `cleanup: "delete"` 옵션을 적절히 활용하세요.
- **맥락 단절:** 각 에이전트는 독립된 세션입니다. 필요한 공통 지식(dgng 페르소나 등)은 메시지를 보낼 때 명시적으로 포함해야 합니다.
- **무한 루프:** 에이전트끼리 서로 질문을 주고받다가 무한 루프에 빠지지 않도록 `runTimeoutSeconds`를 반드시 설정하세요.

### 6. 👨‍🏫 선생님의 통찰
프랭크, '에이전트 위원회'는 결국 **프랭크의 뇌를 확장하는 작업**입니다. 처음에는 "내가 그냥 하고 말지" 싶을 수도 있지만, 일단 이 파이프라인이 구축되면 프랭크는 '작업자'가 아닌 '편집장'의 위치에서 dgng를 운영하게 됩니다. 

가장 추천하는 시작점은 **"리서치 + 초안 작성" 2인 체제**입니다. 이 단계만 자동화되어도 dgng 운영 에너지의 70%를 아낄 수 있습니다. 이제 프랭크만의 '지능형 편집국'을 가동해 보세요!
