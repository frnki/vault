# 26. 영속적 시스템 유지 보수 (Sustainability & Cleanup)

## 1. 왜 이 기능이 중요한가
프랭크의 **dgng** 시스템이 고도화될수록, 데이터 부채와 리소스 낭비가 기하급수적으로 늘어납니다. 무한히 쌓이는 임시 파일, 오래된 세션 기록, 그리고 더 이상 사용되지 않는 스킬들은 시스템의 응답 속도를 늦추고 AI의 판단력을 흐리게 만듭니다. **유지 보수는 단순히 '청소'가 아니라, 시스템의 '엔트로피'를 낮춰 영속성을 확보하는 핵심 전략입니다.**

## 2. 핵심 개념 설명
- **Lifecycle Management:** 파일과 세션의 생성부터 소멸까지의 주기를 관리합니다.
- **Garbage Collection (GC):** 불필요한 데이터를 식별하여 자동 삭제하거나 아카이빙합니다.
- **Resource Optimization:** 최소한의 데이터로 최대한의 맥락을 유지하는 기술입니다.

## 3. 실전 예시 3-5개

### ① 7일 이상 된 임시 세션 자동 정리
```bash
# sessions_list로 오래된 세션 식별 후 삭제 (명령어 예시)
openclaw sessions list --active-minutes 10080 # 7일 이상
# 이후 결과에 따라 cleanup 스크립트 실행
```

### ② 워크스페이스 내 로그 및 덤프 파일 정리
```bash
# 30일이 지난 .log 파일들을 찾아 아카이브 폴더로 이동
find /Users/frank/.openclaw/workspace-teacher/ -name "*.log" -mtime +30 -exec mv {} ./archive/ \;
```

### ③ 메모리 단편화 제거 (Memory Consolidation)
```javascript
// MEMORY.md의 중복된 내용을 통합하고 최신화하는 명령 예시
// "최근 10개의 daily memory를 읽고 MEMORY.md에 핵심만 요약해라"
```

### ④ 사용하지 않는 노드/장치 연동 해제
```bash
openclaw nodes status
# 응답이 없는 노드를 리스트에서 제거하여 폴링 오버헤드 감소
```

## 4. dgng 즉시 적용 가능한 템플릿: 주간 시스템 정화 (Purge) 크론

```json
{
  "name": "Weekly System Purge",
  "schedule": { "kind": "cron", "expr": "0 3 * * 0" }, // 매주 일요일 새벽 3시
  "payload": {
    "kind": "agentTurn",
    "message": "워크스페이스 내 7일 이상 된 임시 파일을 정리하고, MEMORY.md를 최신화하며, 시스템 상태를 점검(healthcheck)한 뒤 리포트를 작성해줘."
  },
  "sessionTarget": "isolated"
}
```

## 5. 함정 및 주의사항
- **과잉 삭제(Over-purge):** 중요한 결정 로그나 프랭크의 선호도가 담긴 메모리 파일을 지우지 않도록 '보존 규칙'을 먼저 세워야 합니다.
- **의존성 붕괴:** 특정 스킬을 삭제할 때, 다른 자동화 스크립트가 해당 스킬을 참조하고 있는지 반드시 확인하세요.
- **백업 부재:** 정리 작업을 수행하기 전, 반드시 전체 워크스페이스의 스냅샷(git commit 등)을 남겨야 합니다.

## 6. 👨‍🏫 선생님의 통찰
