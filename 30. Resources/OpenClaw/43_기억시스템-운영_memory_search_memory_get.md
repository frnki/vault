# 43. 기억 시스템 운영: `memory_search`/`memory_get`

## 1) 왜 중요한가 (dgng 운영 맥락)
운영은 “같은 이슈를 두 번 겪지 않는 것”이 핵심입니다. dgng를 돌리다 보면 장애 대응, 임계치 합의, 설정 변경 이유, 런북 링크가 계속 쌓이는데 채팅 기록만으론 금방 잊힙니다. **메모리 파일 + 의미검색**을 쓰면:
- 과거 합의/선호/결정을 즉시 회수 → 대응 속도↑
- 결정의 근거가 남아 재현 가능 → 품질↑
- 사람 머리 대신 문서 기반 운영 → 일관성↑

## 2) 핵심 개념
- `memory/YYYY-MM-DD.md`(daily): 오늘의 사건/증거/결정 “원시 로그”
- `MEMORY.md`(long-term): 반복 사용되는 **규칙/합의/선호**만 정제 저장
- `memory_search`: 답변 전에 메모리 전체를 의미 기반으로 찾기
- `memory_get`: 필요한 구간만 안전하게 발췌(과다 로딩/노이즈 방지)

## 3) 실전 예시 4개 (코드/명령 포함)

### 예시 1) “지난번 dgng 알람 임계치 합의 뭐였지?”
```tool
memory_search({"query":"dgng 알람 임계치 합의", "maxResults": 5})
```
```tool
memory_get({"path":"MEMORY.md", "from": 1, "lines": 60})
```

### 예시 2) 장애 후 ‘재발 방지 체크리스트’ 재사용
```tool
memory_search({"query":"재발 방지 체크리스트 dgng", "maxResults": 5})
```
→ 있으면 가져와서 이번 장애에 맞게 1~2개 항목만 추가.

### 예시 3) 프랭크 답변 선호(톤/형식) 흔들릴 때
```tool
memory_search({"query":"프랭크 선호 분석적 냉철", "maxResults": 5})
```

### 예시 4) “런북/대시보드 링크 어디였더라”
```tool
memory_search({"query":"dgng runbook 링크", "maxResults": 5})
```

## 4) dgng 즉시 적용 템플릿
오늘 daily 파일에 아래를 그대로 붙여 넣고, 이벤트마다 한 줄씩만 채우세요.
```markdown
## dgng 운영 로그
- 이벤트: (장애/변경/배포)
- 증거: (지표/로그 키워드/스크린샷 링크)
- 결정: (결론 + 근거 1줄)
- 다음 액션: (담당/기한)
- MEMORY 승격 후보: (반복될 규칙/합의만)
```
승격 후보가 2번 이상 반복되면 `MEMORY.md`에 “dgng 운영 원칙” 섹션으로 옮깁니다.

## 5) 함정/주의
- **MEMORY.md를 쓰레기통으로 만들지 말기**: 장기 메모리는 “재사용”만.
- 검색어는 구체적으로(서비스명+지표명+숫자).
- 토큰/개인정보는 기록 금지(필요 시 마스킹).
- 경로/링크가 바뀌면 MEMORY도 같이 업데이트.

## 6) 👨‍🏫 선생님의 통찰
`memory_search`/`memory_get`는 “기억” 도구가 아니라 **운영 표준화 장치**입니다. 사건 직후 3줄만 남겨도, 다음번 대응은 ‘새로 생각’이 아니라 ‘그때의 정답을 다시 실행’이 됩니다. dgng는 이 루프가 쌓일수록 강해집니다.
