# 33. 에이전틱 오케스트레이션: 다중 에이전트 협업 시스템 (Multi-Agent Systems)

## 1. 왜 이 기능이 중요한가 (프랭크의 dgng 운영 맥락)
dgng(디지털 가든) 운영이 고도화될수록, 한 명의 '범용 비서'는 한계에 부딪힙니다. 복잡한 분석, 코드 작성, 창의적 글쓰기를 동시에 수행하면 문맥이 꼬이거나 성능이 저하될 수 있습니다. **에이전틱 오케스트레이션**은 각 분야의 전문가(Sub-Agent)를 소환하여 작업을 분담하고, '선생님'은 이들을 관리하는 지휘자가 되는 시스템입니다. 이는 프랭크의 의사결정 속도를 비약적으로 높여줍니다.

## 2. 핵심 개념 설명
*   **Main Session:** 프랭크와 직접 대화하는 컨트롤 타워 (선생님).
*   **Sub-Agent (Isolated Session):** 특정 목적을 위해 독립된 환경에서 실행되는 전문 에이전트.
*   **Orchestration:** `sessions_spawn`을 통해 전문가를 생성하고, 결과물을 취합하여 최종 가치를 도출하는 과정.

## 3. 실전 예시

### 예시 1: 시장 분석 및 리포트 작성 협업
코드 에이전트가 데이터를 수집하고, 분석 에이전트가 통찰을 도출합니다.
```javascript
// Main Session에서 실행되는 로직 예시
const analyst = await sessions_spawn({
  agentId: "analyst-agent",
  task: "최근 24시간 내 dgng 관련 트렌드 데이터를 분석해서 요약해줘."
});
// 분석 결과가 나오면 메인 세션으로 자동 전달됨
```

### 예시 2: 다중 검증 시스템 (Cross-Checking)
두 개의 다른 모델(예: Gemini 1.5 Pro와 GPT-4o)을 Sub-Agent로 띄워 답변을 비교합니다.
```javascript
await sessions_spawn({
  model: "openai/gpt-4o",
  task: "이 비즈니스 로직의 취약점을 찾아줘."
});
await sessions_spawn({
  model: "google/gemini-1.5-pro",
  task: "동일한 로직의 보안성을 검토해줘."
});
```

### 예시 3: 백그라운드 자동화
프랭크가 다른 일을 하는 동안, 에이전트가 조용히 작업을 완수합니다.
```bash
# CLI에서 직접 서브 에이전트 호출
openclaw spawn --task "지난주 뉴스레터 아카이브하고 태그 달아줘" --label "newsletter-bot"
```

## 4. dgng 즉시 적용 가능한 템플릿: `ORCHESTRATOR.md`
dgng의 `/40. Systems/` 폴더에 아래 템플릿을 저장하고 에이전트에게 읽게 하세요.

```markdown
# 에이전트 협업 프로토콜
1. **분해:** 복잡한 요청은 '수집', '가공', '검증' 단계로 나눈다.
2. **소환:** `sessions_spawn`을 사용하여 단계별 전문가를 배치한다.
   - `agentId: coding-agent` (코드 구현)
   - `agentId: link-learner` (웹 분석)
3. **취합:** 각 에이전트의 출력물을 `MEMORY.md`에 기록하고 최종 보고서를 작성한다.
```

## 5. 함정 및 주의사항
*   **컨텍스트 격리:** 서브 에이전트는 메인 세션의 실시간 대화 내용을 모릅니다. 필요한 정보는 `task` 설명에 명시적으로 포함하거나 공유 파일 경로를 알려줘야 합니다.
*   **비용 관리:** 너무 많은 서브 에이전트를 동시에 실행하면 API 비용이 급증할 수 있습니다.
*   **무한 루프:** 에이전트가 에이전트를 다시 소환하는 로직을 짤 때 종료 조건을 명확히 해야 합니다.

## 6. 👨‍🏫 선생님의 통찰
프랭크, 진정한 효율은 '내가 다 하는 것'이 아니라 '누가 잘할지 정해주는 것'에서 옵니다. 이제 저는 프랭크의 유일한 비서가 아니라, 프랭크를 보좌하는 **전문가 군단의 지휘관**이 되겠습니다. dgng는 단순한 노트 저장소가 아니라, 살아있는 지능형 오케스트라가 될 것입니다.
