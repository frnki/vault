# 02. 세션과 서브에이전트 (Sessions & Sub-agents)

## 1. 왜 이 기능이 중요한가 (프랭크의 dgng 운영 맥락)
프랭크, dgng 운영하시면서 **"이건 시간이 좀 걸리는 리서치인데, 그동안 다른 일을 못 하네"**라고 느끼신 적 없으신가요? 

`sessions_spawn`은 여러분의 복제본(서브에이전트)을 만드는 기능입니다. 복잡한 작업(예: 100개 사우나 리서치, 주간 트렌드 분석 등)을 서브에이전트에게 맡겨두면, 저는 계속해서 프랭크와 대화하며 다른 업무를 처리할 수 있습니다. 즉, **병렬 업무 처리**의 핵심입니다.

## 2. 핵심 개념 설명
- **메인 세션 (Main Session):** 프랭크와 제가 직접 대화하는 현재 창입니다.
- **서브에이전트 (Sub-agent):** `sessions_spawn`으로 생성된 독립된 에이전트입니다. 특정 임무(Task)를 부여받아 배경에서 실행됩니다.
- **격리 (Isolated):** 서브에이전트는 독립된 환경에서 작동하므로, 메인 세션의 흐름을 방해하지 않습니다.
- **결과 보고:** 작업이 끝나면 서브에이전트가 결과를 메인 세션에 보고하고 스스로 종료(cleanup)됩니다.

## 3. 실전 예시

### ① 복잡한 리서치 위임 (Background Research)
프랭크가 다른 작업을 하는 동안 30분 정도 걸릴 리서치를 맡깁니다.
```bash
# 텔레그램에서 직접 명령하거나 제가 실행
sessions_spawn(
  task="성수동 신규 팝업스토어 10곳을 조사해서 각 장소의 특징, 운영 기간, dgng 선정 이유를 정리해줘.",
  label="성수동_리서치",
  runTimeoutSeconds=1800
)
```

### ② 콘텐츠 초안 작성 (Draft Generation)
특정 글쓰기 스타일을 가진 에이전트에게 초안을 맡깁니다.
```bash
sessions_spawn(
  agentId="writer",
  task="이번 주 dgng Pick 제품인 '아르텍 스툴 60'에 대한 인스타그램 캡션 3가지 버전을 작성해줘.",
  label="캡션_작성"
)
```

### ③ 진행 상황 확인 및 메시지 전송
서브에이전트가 잘 하고 있는지 확인하거나 추가 지시를 내립니다.
```bash
# 실행 중인 세션 목록 확인
sessions_list()

# 특정 세션에 추가 지시 (예: label이 '성수동_리서치'인 경우)
sessions_send(label="성수동_리서치", message="아, 카페 노티드 근처 위주로 더 자세히 봐줘.")
```

## 4. dgng 즉시 적용 가능한 템플릿

프랭크의 워크플로우를 위해 아래 구조를 메모장에 복사해두고 필요할 때 지시하세요.

> "선생님, 아래 작업을 서브에이전트에게 맡겨줘:
> 
> **[작업명]** dgng 주간 뉴스레터 리서치
> **[임무]** 핀터레스트와 디자인 웹진에서 이번 주 미니멀리즘 가구 트렌드 키워드 5개를 뽑고 요약해줘.
> **[보고 방식]** 작업 완료 후 텔레그램으로 요약본을 보내고 결과는 옵시디언 '00. Inbox' 폴더에 저장해줘."

## 5. 함정 및 주의사항
1. **타임아웃 설정:** 너무 긴 작업은 `runTimeoutSeconds`를 충분히 주지 않으면 중간에 끊길 수 있습니다 (기본값 확인 필요).
2. **과도한 스폰:** 너무 많은 서브에이전트를 한꺼번에 띄우면 시스템 자원(API 비용 및 메모리)을 소모하므로 적절히 조절하세요.
3. **결과 확인:** `cleanup="delete"`(기본값)로 설정하면 종료 후 세션 기록이 사라집니다. 중요한 결과는 반드시 파일로 저장하거나 메시지로 보고받도록 지시해야 합니다.
