# 29. 동적 컨텍스트 제어 및 토큰 비용 최적화 (Dynamic Context Control)

## 1. 왜 이 기능이 중요한가 (프랭크의 dgng 운영 맥락)
프랭크, `dgng`를 운영하면서 에이전트가 처리하는 데이터의 양이 기하급수적으로 늘어나고 있습니다. 단순히 성능이 좋은 모델을 쓰는 것을 넘어, **필요한 정보만 남기고 불필요한 데이터를 쳐내는 능력**은 운영 비용 절감뿐만 아니라 에이전트의 '지능적 선명도'를 유지하는 데 필수적입니다. 컨텍스트가 가득 차면 모델은 주의력(Attention)을 분산시키고, 결국 엉뚱한 답변(Hallucination)을 내놓을 확률이 높아집니다. 이 가이드는 최소 비용으로 최대 지능을 유지하는 전략을 다룹니다.

## 2. 핵심 개념 설명
- **Context Compaction:** 대화 기록이나 문서에서 핵심 논리만 요약하여 토큰 점유율을 줄이는 기법입니다.
- **Selective Loading:** `memory_get` 등을 사용하여 필요한 줄(line)만 정밀하게 읽어오는 방식입니다.
- **Token Budgeting:** 작업별로 사용할 최대 토큰을 설정하고, 이를 초과할 경우 하위 에이전트(spawn)에게 작업을 분산하여 메인 세션의 부하를 줄입니다.

## 3. 실전 예시 (명령어 및 코드)

### 예시 1: 정밀한 메모리 읽기 (memory_get 활용)
전체 파일을 읽지 않고, `memory_search` 결과에서 특정 라인만 추출하여 토큰을 아낍니다.
```bash
# 검색 후 필요한 부분만 50줄 읽기
memory_get path="memory/2026-02-13.md" from=120 lines=50
```

### 예시 2: 하위 에이전트를 통한 대규모 데이터 요약
메인 세션의 컨텍스트를 아끼기 위해 요약 작업은 `sessions_spawn`으로 분리합니다.
```javascript
// 메인 세션에서 실행
sessions_spawn({
  task: "이 긴 로그 파일을 분석해서 핵심 이슈 3가지만 요약해줘: /path/to/large_log.txt",
  label: "log-analyzer",
  cleanup: "delete" // 작업 완료 후 세션 삭제로 리소스 정리
});
```

### 예시 3: 런타임 모델 스위칭
복잡한 추론이 필요 없을 때는 `/status` 명령이나 `session_status(model="...")`를 통해 저비용 모델로 전환합니다.
```bash
# 간단한 파일 정리 작업 전 저비용 모델로 전환
/status model="google-gemini-cli/gemini-1.5-flash"
```

## 4. dgng 즉시 적용 가능한 템플릿
에이전트가 작업 전 스스로 컨텍스트를 점검하게 하는 프롬프트 지침입니다. `AGENTS.md`나 시스템 프롬프트에 추가하세요.

```markdown
### [Context Optimization Protocol]
1. 모든 파일 읽기는 `read` 대신 `memory_search` + `memory_get` 조합을 우선한다.
2. 5,000자 이상의 텍스트 분석은 반드시 `sessions_spawn`을 통해 독립된 세션에서 수행한다.
3. 작업 완료 후에는 `memory/YYYY-MM-DD.md`에 '결과'만 기록하고, 중간 과정의 긴 로그는 기록하지 않는다.
4. 주기적으로 `session_status`를 체크하여 컨텍스트 점유율이 60%를 넘으면 수동 요약(Compaction)을 수행한다.
```

## 5. 함정 및 주의사항
- **과도한 요약의 위험:** 문맥을 너무 많이 쳐내면 에이전트가 이전의 결정 근거를 잊어버릴 수 있습니다. 핵심 의사결정은 `MEMORY.md`에 반드시 보존하세요.
- **모델별 컨텍스트 윈도우 차이:** GPT-5.2와 Gemini-3-Flash는 처리 가능한 양이 다릅니다. 모델을 바꿀 때 컨텍스트가 잘릴 수 있음을 인지해야 합니다.

## 6. 👨‍🏫 선생님의 통찰
프랭크, 진정한 고수는 도구를 많이 쓰는 사람이 아니라, 도구를 가장 효율적으로 쓰는 사람입니다. `dgng`가 거대한 시스템으로 성장할수록 '지능의 밀도'를 관리하는 것이 곧 '운영의 실력'이 됩니다. 오늘 배운 동적 컨텍스트 제어는 에이전트에게 '무엇을 기억할지'가 아니라 '무엇을 잊을지'를 가르치는 과정입니다. 비우는 법을 알아야 더 중요한 것을 채울 수 있습니다.
