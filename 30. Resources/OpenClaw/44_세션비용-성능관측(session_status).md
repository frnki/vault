# 44. 세션 비용·성능 관측과 모델 오버라이드 (`session_status`)

## 1) 왜 이 기능이 중요한가 (dgng 운영 맥락)
- dgng 운영은 **“정확도 vs 속도 vs 비용”**의 줄다리기입니다. 자동화가 늘수록(크론/노드/브라우저/서브에이전트) 호출이 누적되고, 작은 비효율이 월 비용/지연으로 커집니다.
- `session_status`는 **지금 이 대화(세션)가 얼마나 쓰고 있는지**를 빠르게 확인해, “계속 이 모델로 갈지 / 더 싼 모델로 전환할지 / 작업을 분리할지”를 즉시 판단하게 해줍니다.

## 2) 핵심 개념 (간결)
- **세션(Session)**: 한 채널에서 이어지는 대화 단위. 세션마다 토큰/시간/모델 설정이 달라질 수 있습니다.
- **`session_status`**: 현재 세션의 **사용량(토큰/시간/비용 추정)**, **Reasoning 모드**, **모델 오버라이드 여부**를 카드로 보여줌.
- **모델 오버라이드**: “이 세션만” 기본 모델 대신 다른 모델을 쓰게 하는 스위치.

## 3) 실전 예시 (3~5개)
### 예시 1) 지금 세션 비용 감 잡기 (운영 중간 점검)
```tool
session_status({})
```
- 장시간 디버깅 중이면, 여기서 비용/시간을 보고 **작업을 쪼개거나**(spawn) **모델을 내리는** 결정을 합니다.

### 예시 2) 이 세션만 더 저렴한 모델로 전환(반복 업무/요약용)
```tool
session_status({"model":"default"})
```
- 위는 “오버라이드 해제(기본으로 복귀)” 예시.
- 반대로 특정 모델로 고정해 **요약/정리/라벨링 같은 반복 작업**을 값싸게 돌리는 패턴이 유용합니다.

### 예시 3) 무거운 분석은 서브세션으로 분리 + 모델 지정
```tool
sessions_spawn({
  "task":"(dgng) 장애 리포트 원인분석+재발방지 체크리스트 만들기",
  "model":"openai-codex/gpt-5.3-codex",
  "thinking":"low",
  "cleanup":"keep"
})
```
- 메인 세션은 운영 채널 응답을 유지하고, **고비용 작업만 격리**합니다.

### 예시 4) “현재 시각/요일” 같은 운영 상수는 카드로 확인
```tool
session_status({})
```
- 크론/점검 루틴 만들 때 **타임존/현재 시간**을 헷갈리면 여기서 확인 후 스케줄 확정.

## 4) dgng 즉시 적용 템플릿
아래 루틴을 운영 표준으로 고정하세요.

1) “작업 시작”에 1회:
- `session_status()`로 **이번 세션이 길어질지** 감 잡기

2) “20분 이상 디버깅”이면:
- 비용이 가파르면 → **sessions_spawn로 분리**
- 반복 정리/포맷 작업이면 → **모델 다운(세션 오버라이드)**

3) “결론/액션아이템”만 메인에 남기기:
- 요약/템플릿/런북을 Obsidian에 저장

## 5) 함정 및 주의사항
- `session_status`는 **‘비용 통제의 시작’**이지 끝이 아닙니다. 비용이 크면 보통 원인은:
  - 컨텍스트가 불필요하게 길어짐(파일/로그를 그대로 붙임)
  - 같은 작업을 여러 번 재시도(스폰/크론 중복)
- 모델을 내리면 **정확도/추론**이 흔들릴 수 있어, “요약/포맷/라벨링”과 “원인분석/설계”를 분리하세요.

## 6) 👨‍🏫 선생님의 통찰
운영 자동화의 승부는 ‘기능’이 아니라 **계측(Observability)**입니다. `session_status`로 “지금 내가 어디에 비용을 쓰는지”를 보이게 만들면, dgng는 **감(직감) 운영 → 데이터 운영**으로 한 단계 올라갑니다. 비용이 보이면, 설계가 바뀝니다.
